3. DATA ACQUISITION
===================

Acquisition context:
Real-world vehicle operation using onboard battery management
systems.

Sampling frequency:
0.1 Hz, corresponding to approximately one sample every
10 seconds.

Recording behavior:
BMS recording is active during monitored vehicle operation and
stops when the vehicle is switched off. Rows recorded while the
vehicle is off carry sentinel values (see Section 7).

Operational states:

* Driving
* Charging
* Rest
* Charging complete / taper

Environmental conditions:
Uncontrolled ambient conditions encountered during real-world
vehicle operation.

=======================

Driving:
Natural user-dependent driving including acceleration,

Driving environments:
City and highway operation.

Charging:
Real-world charging with different charging rates and charging

Fast charging:
Up to approximately 0.8C (approximately 124 A at 155 Ah).

Charging behavior:

Temperature:

DoD:
Variable and determined by real-world driving and charging

============================================================
5. AVAILABLE DATA
=================

Column list (12 columns per CSV file):

* terminaltime        - numeric seconds counter (not an epoch);
                        sampling interval is ~10 s
* soc                 - state of charge (%)
* speed               - vehicle speed
* totalodometer       - cumulative mileage (km)
* chargestatus        - operating mode code (see Section 6)
* totalvoltage        - pack terminal voltage (V)
* totalcurrent        - pack terminal current (A)
* minvoltagebattery   - minimum cell voltage (V)
* maxvoltagebattery   - maximum cell voltage (V)
* mintemperaturevalue - minimum cell temperature (deg C)
* maxtemperaturevalue - maximum cell temperature (deg C)
* batteryvoltage      - tilde-separated string of all 96 cell
                        voltages (e.g. "3.643~3.644~3.642~...")
* probetemperatures   - tilde-separated string of all probe
                        temperatures

Note on stringified columns:
"batteryvoltage" and "probetemperatures" pack multiple per-cell
or per-probe values into a single text field. They are not
scalar measurements and are excluded from signal-level checks in
the quality scorecard.

Cell-level measurements:
Voltage measurements are available for all 96 cells in each
battery pack, encoded in the "batteryvoltage" column.

Processed data:

* Capacity-based SOH labels
* Charge-capacity sequences (Q_HI)
* Temperature sequences (T_HI)
* Cell-voltage inconsistency maps
* 15 engineered point features

SOH labels:
SOH is obtained using Ah integration with OCV correction.


============================================================
6. OPERATING MODE CODES (chargestatus)
======================================

Codes observed in the raw data and their inferred meaning,
derived from the joint distribution of current, speed, and SOC:

* 0   - Rest / parked             (mean I = 0 A, SOC near 0)
* 1   - Charging                  (mean I = -53 A, speed near 0)
* 3   - Driving / discharge       (mean I = +8.5 A, speed ~19 km/h)
* 4   - Charging complete / taper (mean I ~ -1.5 A, SOC ~93%)
* 255 - Sensor error marker       (every such row has
                                    totalcurrent = -1000.0 A exactly)

The quality scorecard drops all chargestatus = 255 rows before
running any signal-level check.

Current sign convention:
Negative = charging, positive = discharging.
This is inferred from the raw data (the paper and README do not
state a convention). The quality scorecard verifies it dynamically
by comparing current sign to chargestatus. Driving includes regen
braking, so ~15-20% of driving rows are legitimately negative.


============================================================
7. PHYSICAL ENVELOPE AND SENTINELS
==================================

The physical envelope used by the quality scorecard's
plausibility check is derived as follows:

Pack voltage: 240 - 408 V
  Lower bound: 96 cells x 2.5 V/cell (standard NCM discharge
               cutoff) = 240 V
  Upper bound: 96 cells x 4.25 V/cell = 408 V
               (the paper explicitly states a 4.25 V per-cell
               upper cutoff for feature extraction)

Pack current: -400 - +400 A
  QC guard rail, not paper-derived. The paper does not state an
  absolute current bound. Observed per-vehicle peaks in the
  exploration were approximately +340 A during discharge and
  approximately -200 A during charging (after removing the
  -1000 A sentinel).

Battery temperature: -20 - +60 C
  Generic Li-ion operating envelope. The paper does not state a
  thermal operating window. Observed range after sentinel removal
  was approximately +3 to +44 C.

SOC: 0 - 100 % (standard definition).

Sentinel values (written by the BMS as placeholders, not
measurements; the scorecard drops these rows before any
plausibility check):

* totalcurrent = -1000.0 A exactly
      Appears on every row with chargestatus = 255.
* totalvoltage = 0.0 V exactly
      Appears when the vehicle is switched off and the BMS is
      asleep. Present in the majority of vehicle files.
* maxtemperaturevalue = -40.0 C exactly
      Temperature-probe-not-connected marker. Present in many
      vehicle files, always with the same exact value.

============================================================
11. QUALITY-ASSESSMENT NOTES
============================

Design rule:
Hardcode only facts that cannot be determined from the raw data
files at all. Everything else is computed dynamically.

Sampling strategy:
The full dataset is ~180 GB across 94 files in the current
snapshot. The quality scorecard samples the first 200,000 rows
per file (approximately 23 days of continuous operation per
vehicle) rather than reading all rows.

Excluded columns:
"batteryvoltage" and "probetemperatures" are tilde-separated
strings of per-cell or per-probe values and are excluded from
signal-level checks. The already-extracted min/max columns
(minvoltagebattery, maxvoltagebattery, mintemperaturevalue,
maxtemperaturevalue) provide the cell-level envelope used by
the plausibility check.

Time column handling:
"terminaltime" is a numeric seconds counter (not an epoch
timestamp). Sampling interval is ~10 s. Time-based checks treat
the column as seconds.

Sign-convention check:
The scorecard verifies the current sign convention dynamically
against chargestatus and applies a regen tolerance on the
driving side (>= 75% positive-dominant is accepted, since
regenerative braking legitimately produces negative current
during deceleration).

METADATA_ONLY:
Calendar aging is the only metadata-only aspect for this dataset.
Dynamic load profiles and real-world operation are present by
construction and are scored dynamically, not as metadata facts.
